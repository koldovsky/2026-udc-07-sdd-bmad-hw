**Фіча:** знижки з `materials/feature-request.md`
**Хост / модель:** Cursor / Grok 4.6 (обидва прогони)

Прогін A — цей же чат, `/opsx-apply` за `docs/spec/pricing-discounts.md`.  
Прогін B — ізольований worktree без спеки ([ad-hoc run](0d6ef2b9-dd80-47a1-a40e-88be6b3d7712)), агенту дано лише тікет + засіяні `types.ts` / `pricing.ts`. Код B **не зливався** в основну гілку; лежить у worktree `adhoc-runb-a7f3c2e1`.

## Прогін A — зі специфікацією

Агенту дано `docs/spec/pricing-discounts.md` і сказано реалізувати за нею.

- **Що вийшло:** `app/src/discounts.ts` (`priceOrder(order, catalog, nowIso: string) → PriceBreakdown` з пʼятьма цілими полями), тести `app/src/discounts.test.ts`, реекспорт з `index.ts`. Алгоритм §5 дослівно: рівень по рядках, потім купони, `floor((r * p + 50) / 100)`, без `Date.now()`.
- **Рішення щодо неоднозначностей:** збіглися зі спекою D-1…D-14. Відступів не було; після typecheck лише підчистили індексацію під `noUncheckedIndexedAccess` (поведінка та сама).
- **Тести:** 16 іменних `AC-1`…`AC-16` (спочатку 12 зі спеки, +3 після зворотної перевірки Task C, **AC-16 додано після прогонів A/B**). Є порожнє замовлення, знижка > суми, пів копійки, два рядки 15+15, порядок списання фіксу. Разом з засіяними — 24 зелені.

## Прогін B — ad-hoc

**Новий** чат: окремий агентний сеанс без історії прогону A (субагент в ізольованому worktree; повідомлення й рішення чату A йому не передавались). Агенту дано **лише** `materials/feature-request.md` — без спеки. Той самий хост і модель. Спеку, `openspec/` і наявний `discounts.ts` читати заборонено.

- **Що вийшло:** перезаписаний `app/src/discounts.ts` у worktree. Сигнатура інша: `priceOrder(order, catalog = [], now: Date = new Date())`. У breakdown зайві поля, яких спека не просила: `totalDiscountKopecks`, `merchandiseKopecks`, `appliedCouponCodes`. Залишки ведуться **по категоріях** (три відра), не по рядках. Нескоупований фікс з’їдає відра в порядку `standard → fresh → digital`.
- **Які розвилки він вирішив мовчки:**
  - stacking послідовно (рівень, потім купони) — як A, без питання;
  - `Math.round((amount * percent) / 100)` з float, на агрегаті категорії, не ціла формула по рядку;
  - коди: `trim` + **case-insensitive**;
  - годинник за замовчуванням `new Date()`;
  - відсоток 150% не skip, а `min(round(1.5 × база), залишок)`;
  - зайвий API (`appliedCouponCodes` тощо).
- **Тести:** 19 нових (назви на кшталт `applies gold 10% to merchandise only`, не AC-id). Є empty, clamp фіксу, half-kopeck (1 коп. × 50% → 1). Немає сценарію «два рядки по 15 коп. у одній категорії». `npm test` 27/27, typecheck ok, **0** повторних правок.

## Порівняння рішень

По кожній розвилці зі спеки — що обрав агент без неї.

| Розвилка | A (за спекою) | B (ad-hoc) | Збіг? |
|---|---|---|---|
| D-1 складання знижок | послідовно: рівень, потім купони в порядку введення | те саме (тест: Gold потім 10% → 810 грн товарів, не 800) | так |
| D-2 база знижки | лише товари; доставка після | те саме | так |
| D-3 кілька промокодів | усі валідні, дубль один раз | те саме | так |
| D-4 округлення | ціле `floor((r*%+50)/100)` на **рядку** | `Math.round((amount * %)/100)` на **категорії**, float | ні |
| D-5 купон на категорію | від залишку рядків цієї категорії | від залишку відра категорії | майже* |
| D-6 `minSubtotalKopecks` | початковий `subtotalKopecks` | те саме, є окремий тест | так |
| D-7 відʼємний підсумок | залишок ≥ 0, доставка лишається | clamp, shipping 49 грн | так |
| D-8 прострочений | тихий skip, без throw | те саме | так |
| D-9 «зараз» | обовʼязковий `nowIso: string`, без `Date.now()` | `now?: Date = new Date()` | ні |
| D-10 код у каталозі | точний рядок, регістр важливий | `trim` + lowercase | ні |
| D-11 фікс зʼїдає рядки | порядок `order.items` | нескоупований: standard→fresh→digital | ні |
| D-12 рівень по рядках чи підсумку | по рядках (15+15 Gold → **4**) | по категорії (два `standard` 15+15 → **3**) | ні |
| D-13 порожнє замовлення | нулі, `shippingKopecks([])` як є | те саме | так |
| D-14 доставка після знижок | `shippingKopecks(order)`, не з суми | те саме | так |

\*На одному рядку на категорію D-5 збігається; роз’їзд той самий, що D-12, щойно у категорії кілька позицій.

Додатково B вигадав поля breakdown і нескоупований порядок відер — цього не просив жоден AC спеки.

## Висновок

Без спеки агент **мовчки** закрив 14 розвилок і влучив у 8 з них (складання, база, кілька кодів, мін. сума, підлога, skip простроченого, порожній кошик, доставка). Розійшовся там, де тікет мовчить найневинніше: **округлення й база рядка**, **годинник**, **регістр коду**, **порядок списання фіксу**. На 1000 грн Gold+10% обидва дають 810 грн товарів — рев’ю «на око» сказало б «ок». Різницю 15+15 коп. Gold (4 vs 3) і флакі `new Date()` без спеки на PR легко пропустити: B навіть має тест на half-up, але на іншому прикладі (1×50%), де обидві формули дають 1.

Спека коштувала ~25 хв. На **цій** фічі вона окупилась не швидкістю (B швидший і з першого разу зелений), а тим, що зафіксувала копійки й детермінований час. Вигаданої переваги «агент без спеки склав би відсотки адитивно» немає — B склав послідовно сам. Якби тікет одним рядком сказав «ціла формула по рядку, `now` ззовні, код case-sensitive», доброго тікета вистачило б. Повний документ на 14 рішень вартий, коли роз’їзд у 1 копійку вважається багом, а не смаком.
