# Специфікація: знижки на checkout (рівень лояльності + промокоди)

> Головний критерій якості: **два різні інженери (або два прогони агента), що
> реалізують цю специфікацію, мають отримати однакову поведінку.** Якщо
> лишається місце для «ну, я думав, малося на увазі…» — специфікація ще не
> готова.

**Статус:** agreed
**Джерело:** `materials/feature-request.md`
**Автор рішень:** учасник WS7

---

## 1. Мета

На checkout клієнт із рівнем Silver або Gold отримує свою знижку на товари, і
може додати один або кілька валідних промокодів. Обидві вигоди видно в
розбитті суми (окремо рівень, окремо промокоди). Підсумок до сплати — цілі
копійки, без від’ємної вартості товарів. Доставка лишається окремим рядком і
не зменшується знижками.

## 2. Поза скоупом

Свідомо не робимо в цій ітерації:

- UI checkout, повідомлення на екрані, аналітика, збереження «код уже
  використано».
- CRUD каталогу промокодів, ліміт використань, персональні коди.
- Зміна сигнатур у `app/src/pricing.ts` і форм у `app/src/types.ts`.
- Знижка на доставку окремим правилом, безкоштовна доставка від суми.
- Валідація «брудних» рядків замовлення (від’ємна ціна, від’ємна кількість).
  Рушій рахує з переданих чисел: `unitPriceKopecks * quantity` як у
  `lineTotalKopecks`.
- Винятки з функції ціноутворення: вона завжди повертає розбиття, ніколи не
  кидає через промокод.
- Перестановка або «найвигідніший набір» промокодів.

### Нормативний алгоритм (цілі копійки)

Нехай `subtotal = subtotalKopecks(order)`, `shipping = shippingKopecks(order)`.

**Відсоток → копійки (half-up):** для цілих `amount >= 0` і `percent` 0–100:

```
product = amount * percent
q = trunc(product / 100)
r = product % 100
discount = (r >= 50) ? q + 1 : q
```

Не використовувати ділення з плаваючою комою для сум.

1. `remaining = subtotal`
2. `tierDiscount = percentToKopecks(remaining, tierPercent(order))`; `remaining -= tierDiscount`
3. Побудувати список **унікальних** уведених кодів: іти по `order.coupons`, для кожного `trim`, порожній рядок пропустити; якщо цей нормалізований код (lower case) уже бачили — пропустити; інакше знайти в каталозі перший `Coupon`, у якого `trim(code).toLowerCase()` збігається. Немає в каталозі — пропустити.
4. Для кожного знайденого купона:
   - якщо `Date.parse(expiresAt)` не число **або** `asOf.getTime() >= Date.parse(expiresAt)` → пропустити;
   - якщо задано `minSubtotalKopecks` і `subtotal < minSubtotalKopecks` → пропустити;
   - якщо задано `category` і жоден рядок не має цієї категорії → пропустити;
   - `categoryBase` = сума `lineTotalKopecks` рядків цієї категорії, або `remaining`, якщо категорії немає;
   - якщо `kind === "percent"`: `raw = percentToKopecks(categoryBase, value)`;
   - якщо `kind === "fixed"`: `raw = value`;
   - `applied = min(raw, categoryBase, remaining)` (для коду без категорії `categoryBase` уже дорівнює `remaining`, тож `min` не змінює сенсу);
   - `couponDiscount += applied`; `remaining -= applied`
5. `total = remaining + shipping`

Поля розбиття: `subtotalKopecks = subtotal`, `tierDiscountKopecks = tierDiscount`, `couponDiscountKopecks = couponDiscount`, `shippingKopecks = shipping`, `totalKopecks = total`. Інваріант: `subtotal - tierDiscount - couponDiscount === remaining >= 0` і `total === remaining + shipping`.

## 4. Критерії приймання

## 5. Контракт

Новий модуль `app/src/discounts.ts`. Типи `Order`, `LineItem`, `Coupon` —
лише з `app/src/types.ts` (не змінювати). Підсумок товарів, доставка і
відсоток рівня — лише через наявні `subtotalKopecks`, `shippingKopecks`,
`tierPercent` з `app/src/pricing.ts` (не змінювати сигнатури і поведінку).

Публічна поверхня (named export). Реекспорт з `app/src/index.ts`.

```ts
import type { Order, Coupon } from "./types.js";

/** Усі поля — цілі копійки, >= 0. */
export interface PriceBreakdown {
  subtotalKopecks: number;
  tierDiscountKopecks: number;
  /** Сума знижок усіх застосованих промокодів; не розбиття по кожному коду. */
  couponDiscountKopecks: number;
  /** Товари після рівня і промокодів. */
  remainingGoodsKopecks: number;
  shippingKopecks: number;
  totalKopecks: number;
}

/**
 * Рахує чек за розділом 3 (нормативний алгоритм).
 * `order.coupons` — коди, які клієнт увів.
 * `catalog` — доступні промокоди; коди, яких немає в `order.coupons`, не діють.
 * `asOf` — момент перевірки `expiresAt`; усередині немає `Date.now()`.
 * Не кидає через промокоди (D-8, D-12, D-24).
 */
export function priceOrder(
  order: Order,
  catalog: Coupon[],
  asOf: Date,
): PriceBreakdown;
```

Інваріанти для кожного поверненого розбиття:

- усі шість полів — цілі числа `>= 0`;
- `remainingGoodsKopecks === subtotalKopecks - tierDiscountKopecks - couponDiscountKopecks`;
- `totalKopecks === remainingGoodsKopecks + shippingKopecks`;
- `shippingKopecks === shippingKopecks(order)` з `pricing.ts`.

Інших публічних функцій рушій не додає. Тести — `app/src/discounts.test.ts`,
назви `it(...)` починаються з `AC-N:` як у розділі 4.
